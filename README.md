## 工作方式

优先梳理证明线路、定义、反例与文献。避免非必要编码、门限和哈希检查、强制 CI 或形式化工程。**数学证明暂时不需要程序性验证**；已有程序和证书按需参考，不要求每轮重跑。

允许直接留下直觉、部分证明、失败尝试和待查文献，写清楚条件和缺口。保存或合并草稿不等于认证其中所有主张。旧包的工程化验收建议不覆盖当前 AGENTS.md。

[Issues](https://github.com/YinzhuCheng/one-third-two-thirds/issues) 用于数学讨论；提交或 PR 用于保存研究增量。每轮留下实际结论、失败原因、依赖和下一步，不必建立复杂管理设施。
